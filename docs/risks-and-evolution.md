# 风险与演进

## 风险清单

| 风险 | 影响 | 当前缓解 | 演进方向 |
| --- | --- | --- | --- |
| 本地 PostgreSQL 容器非高可用 | dev 环境单实例，容器或卷损坏会影响本地数据 | 数据卷持久化；Flyway 可重建结构；种子数据可重新导入 | 生产使用托管 PG 多可用区；本地数据不作为权威数据 |
| 热门书行锁竞争 | 借阅延迟上升 | 事务短小、只锁单本书 | 监控锁等待；预约队列/分片库存 |
| 容量触发器每次计数 | 大借阅量下插入变慢 | `(book_id,status)` 索引 | 维护活跃计数或异步对账 |
| 偏移分页深页 | 大 offset 扫描变慢 | `size <= 50`；稳定排序 | 游标分页 |
| 包含搜索无索引 | 大目录搜索慢 | 当前数据量小；`locate` 语义安全；搜索结果缓存 | PG `pg_trgm`/FTS 或搜索引擎 |
| 本地缓存跨实例延迟失效 | 其他节点最多 TTL 内看到旧可借数量 | TTL 30s；缓存不参与超借判断 | 需要强一致展示时切换 Redis + 失效广播 |
| JWT 未校验 audience、未限流 | 生产安全加固不足 | issuer/exp/sub 校验、方法级授权 | 增加 audience、算法白名单、WAF/负载均衡限流 |
| 开发令牌端点 | 被误开到生产会允许任意身份 | `@Profile("dev")` + HMAC 模式双重条件 | 生产镜像不激活 dev profile；启动自检/告警 |
| Flyway 并发启动 | 多实例同时迁移可能等待/失败 | PG Flyway 锁串行化 | 独立迁移 Job，应用启动只校验 |
| 书名读取依赖 Book 存在 | 书目被删除时显示 Unknown book | 当前无删除 API；外键保护 | 软删除或事件驱动快照 |
| 逾期规则缺失 | 无法计算罚金/通知 | 保存 `dueAt`，不假装已实现 | 引入定时任务 + outbox + 通知服务 |
| 无用户目录 | 无法展示用户资料 | 身份由 IdP 管理 | 对接 IdP/用户服务 |

### 推荐的演进顺序

1. 生产化：OIDC audience 校验、WAF/负载均衡限流、集中指标/追踪、独立迁移流程。
2. 业务补全：逾期批处理、通知、预约/续借；先以模块内定时任务起步，确有跨服务需求再引入消息队列。
3. 性能：根据指标调整缓存 TTL/容量、游标分页、FTS；跨实例强一致需求出现时再引入 Redis，不以“架构完整性”为由提前引入组件。
4. 拆分：只有在团队边界、发布节奏或负载明确要求时，才把 catalog/loan 拆为独立服务，并同时设计事件契约与数据迁移。

## 未实现功能

| 未实现 | 原因 |
| --- | --- |
| 逾期调度、罚金、催还通知 | 需要定时任务、时区/计费规则和通知渠道；本作业只保存 `dueAt`，把规则变化留给业务演进 |
| 预约/排队/续借 | 会引入新的聚合和公平性规则，超出核心借还闭环 |
| 全文搜索、推荐 | 当前 `locate` 搜索满足演示；大规模检索应使用 PostgreSQL FTS/trigram 或独立搜索引擎 |
| 真实 IdP、用户注册 | 本地用 dev token 保证 5 分钟可运行；生产通过 OIDC issuer 对接 |
| Kafka/消息队列、Redis/分布式缓存、分布式锁 | 没有异步流程；书目缓存使用进程内 Caffeine，借阅一致性由数据库事务和行锁保证。跨实例强一致缓存需求出现前不引入 Redis |
| 微服务、服务发现、配置中心 | 业务边界尚不需要独立部署；模块化单体保留清晰边界，未来可拆分 |
| 图书管理后台 | 题目聚焦读者侧 API 与并发正确性；书目由 Flyway 种子/运维导入 |
| 指标大盘、链路追踪后端 | 已提供 traceId、健康探针与结构化日志；生产可接 Prometheus/OpenTelemetry，不在本地强制搭基础设施 |

## 关键权衡

- **统一使用 PostgreSQL**：本地 Compose、集成测试和生产跑同一套 `common + postgresql` Flyway 迁移和行锁语义，避免本地与生产行为分叉；代价是本地开发需要 Docker/PostgreSQL，而不再是零依赖的单文件数据库。
- **悲观行锁优先**：借书先锁 `book` 行，再统计并插入，避免“先查后插”的竞态；`@Version` 和数据库部分唯一索引/触发器是第二道防线。详情见[并发与一致性](concurrency-and-cache.md#并发与一致性)。
- **偏移分页**：实现简单、UI 友好；数据量很大或深分页时再切换游标分页。
- **开发令牌**：只在 `dev` profile 且 `hmac` 模式启用；生产必须关闭并使用 OIDC。
